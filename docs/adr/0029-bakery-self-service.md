# ADR-0029: 베이커리 8종과 손님 직접 픽업·계산 방식

- 상태: 대체됨 (ADR-0030 포스기 입력 부분, ADR-0031 진열장 위치·팝업 부분)
- 날짜: 2026-11-12
- 관련 명세: SFR-010, SFR-026, SFR-027, SFR-056, SFR-068

## 맥락

사용자는 베이커리를 8종으로 늘리고 샌드위치, 베이글, 와플, 허니브레드, 크로크무슈를 추가하며, 손님이 진열장에서 직접 가져오면 계산만 하는 방식으로 변경하기로 했다. 신규 가격은 임시값 사용을 승인했다. 기존에는 플레이어가 진열장에서 디저트를 접시에 담아 픽업대에 서빙했다.

## 결정

- 딸기 케이크·크루아상·쿠키를 유지하고 요청한 5종을 추가한다. 저장 호환을 위해 기존 `Dessert` 분류와 id는 유지한다.
- 손님은 진열장으로 이동해 재고가 있는 베이커리를 가져온 뒤 계산대 줄에 선다. 가져올 때 재고를 차감하고, 경쟁으로 수량이 부족하면 남은 수량만 가져온다.
- 가져온 베이커리는 포스기 목록에 자동 등록하며 수량 변경·삭제·추가 입력 없이 실물대로 계산한다. 음료는 기존처럼 직접 입력한다.
- 영수증에는 베이커리를 포함한다. 제조용 주문 내역과 픽업대 자리에는 음료만 표시한다. 만족도의 제조·누락 판정도 음료만 대상으로 한다.
- 베이커리는 별도 제조·접시 사용·픽업대 서빙이 없다. 포장으로 제공하여 설거지 접시를 추가하지 않는다.
- 결제 전 이탈하면 가져온 베이커리를 반납한다. 음료를 받기 전 이탈·영업 종료 시 기존 전액 환불 정책과 함께 베이커리 재고도 복구한다. 정상 서빙 후에는 복구하지 않는다.
- 기존 밸런스의 가격·아이콘·초기 재고 설정을 보존하고 누락된 베이커리 정의만 추가한다. 새 게임은 8종 각 5개로 시작하고, 기존 저장의 신규 재고는 구매해서 채운다. 테스트용 전체 재고 모드는 기존 규칙대로 적용한다.
- 신규 매입가·판매가는 GAME_DATA에 임시값으로 기록한다.

## 검토한 대안

- 플레이어가 베이커리를 꺼내 서빙: 사용자 요청과 맞지 않는다.
- 베이커리를 수동으로 포스기에 입력: 실물과 입력 수량이 달라질 수 있어 자동 계산을 채택한다.
- 결제 시 재고 차감: 결제 전 여러 일행이 마지막 재고를 동시에 가져갈 수 있으므로 집는 순간 차감한다.

## 결과

ADR-0018의 디저트 수동 배치·서빙 부분을 대체한다. 음료 픽업·오입력·선입선출 판정은 유지한다. 밸런스 에셋은 Unity 메뉴로 갱신하며 YAML을 직접 수정하지 않는다. 신규 5종 전용 그림은 아직 없어 이름과 재고·가격으로 표시한다. Unity에서 진열장 동선, 포스기 자동 계산, 재고 복구와 영업 종료를 검증한다.

### Unity 확인 절차

1. Unity 6000.6.4f1에서 스크립트 컴파일 후 `CafeTime > Create Game Balance`를 실행해 기존 에셋에 누락된 5종을 저장한다. 기존 가격과 재고 설정이 유지되는지 확인한다.
2. 새 게임 오픈 준비의 디저트 탭에서 8종 구매를 확인한다. 이어하기에서는 신규 품목을 구매한다 (테스트용 전체 재고 모드가 켜져 있으면 자동 보충).
3. Cafe 씬에서 베이커리를 고른 손님이 진열장 → 포스기 순서로 이동하는지 확인한다. 진열장을 열어 8개 카드가 두 줄로 표시되고 플레이어 손으로 꺼낼 수 없는지 확인한다.
4. 포스기를 열어 가져온 품목이 자동 등록되고 수량·삭제·입력 취소로 바뀌지 않는지 확인한다. 음료를 입력하고 결제해 합계와 영수증을 확인한다.
5. 주문 내역·픽업대에는 음료만 표시되는지, 음료를 정상 서빙했을 때 베이커리 누락 감점이 없는지 확인한다.
6. 테스트용 전체 재고 모드를 끄고 베이커리 마지막 1개를 여러 손님이 선택하게 해 음수 재고가 생기지 않는지 확인한다. 결제 전 이탈, 음료 대기 중 이탈, 영업 종료에는 미완료 주문의 재고·금액이 복구되고 정상 완료 주문은 유지되는지 확인한다.

씬·프리팹 재빌드 없이 기존 씬의 스크립트에서 적용한다. 신규 5종 전용 아이콘은 후속 아트 작업으로 남아 있다.
