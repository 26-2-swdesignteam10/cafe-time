# ADR-0001: 설계 결정을 ADR로 기록한다

- 상태: 승인
- 날짜: 2026-11-02

## 맥락

팀원 여러 명이 기능을 나눠 개발하고, 코드 일부는 AI 도구(Claude Code, Codex)로 작성한다.
"왜 이 구조로 만들었는지"가 코드와 커밋 메시지에 흩어져 있으면, 새로 합류한 사람이나 AI 도구가 기존 결정을 모르고 반대로 구현하기 쉽다.

## 결정

여러 사람에게 영향을 주는 설계 결정은 `docs/adr/` 에 ADR(Architecture Decision Record)로 남긴다.

- 파일 이름: `NNNN-영문-요약.md` (번호는 4자리, 순서대로)
- 형식: `template.md` (상태 / 맥락 / 결정 / 검토한 대안 / 결과)
- 생성은 `bash docs/adr/new-adr.sh "제목" english-slug` 로 한다. 번호 매기기와 목록(`docs/adr/README.md`) 추가가 자동으로 된다.
- 상태: AI 에이전트나 개인이 제안한 결정은 `제안`, 사용자·팀이 확정하면 `승인`.
- 한 번 승인된 ADR은 내용을 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고 기존 ADR 상태를 `대체됨 (ADR-NNNN)` 으로 바꾼다.
- 결정이 생긴 작업과 **같은 PR**에서 ADR을 추가한다. AI 에이전트도 같은 규칙을 따르도록 `AGENTS.md` 에 적는다.
- CI가 모든 ADR이 목록에 있고 상태가 적혀 있는지 검사한다.

## 검토한 대안

- README에 모두 적기: 규칙(무엇을)은 남지만 이유(왜)와 버린 대안이 남지 않고, 문서가 계속 길어진다.
- GitHub Wiki: 코드와 따로 관리되어 PR 리뷰 대상이 되지 않는다.

## 결과

- 설계 변경이 PR에서 코드와 함께 리뷰된다.
- 작은 결정까지 ADR로 쓰면 부담이 커지므로, 되돌리기 어렵거나 여러 기능에 영향을 주는 결정만 기록한다.
