# ADR-0048: DAY 6 인플루언서는 영업 중 대화창으로 대표 메뉴 촬영을 요청하고, 결과로 평판과 다음 날부터의 손님 수가 바뀐다

- 상태: 제안
- 날짜: 2026-11-24
- 관련 명세: SFR-008, SFR-009, SFR-024, SFR-068, SFR-071, SFR-072
- 관련 ADR: ADR-0042(단체 주문 이벤트), ADR-0040(진동벨 호출), ADR-0022(선입선출)

## 맥락

명세서 SFR-009 의 DAY 6 은 "인플루언서 방문 이벤트 - 대표 메뉴 추천 및 촬영 요청, 대응 결과에 따라 평판과 이후 손님 수 변화" 한 줄뿐이다. 요청 시점, 대표 메뉴, "대응 결과" 의 기준, 평판·손님 수 변화량은 정해져 있지 않다.

DAY 4 단체 주문(ADR-0042)이 이미 "영업 중 대화창으로 수락/거절 → 포스기 없이 주문 등록 → 마감까지 픽업대 진동벨 호출" 구조를 만들어 두었으므로, 같은 흐름을 재사용하면 새 UI·아트 없이 구현할 수 있다.

## 결정

1. **영업 중 대화창으로 요청한다.** DAY 6 의 정해진 게임 시각(기본 13:00)에 `InfluencerManager` 가 단체 주문과 같은 `EventDialog` 를 연다. 화자 "인플루언서", 손님 2 그림으로 대표 메뉴 추천과 촬영을 요청하고 수락/거절 버튼을 띄운다. 대화 중에는 게임 시간과 손님이 멈춘다(ADR-0042 와 같음). 입장 마감 뒤에는 요청하지 않는다.
2. **대표 메뉴는 `GameBalance` 설정으로 정한다** (기본 ICE 바닐라라떼). 수락이 곧 "사장이 대표 메뉴를 추천하고 촬영을 허락함" 이다. 수락하면 포스기 입력 없이 대표 메뉴 1잔 주문이 등록되고, 영수증·트레이의 이벤트 줄에 글자 이미지 없이 "인플루언서 ~15:00" 을 폰트로 표시한다.
3. **마감 시각(기본 15:00)까지 픽업대 트레이에 놓고 진동벨로 호출한다.** 인플루언서는 픽업대 앞에서 기다리고 있다고 보고 바로 받아 간다. 대표 메뉴와 맞고 실패 등급이 아니면 음료 값을 받는다. 득점은 일반 주문처럼 완료 1건 + 만족도(메뉴·등급, 대기 감점 없음).
4. **"대응 결과" = 받아 간 대표 메뉴의 등급.** 완벽 → Great, 좋음 → Good, 나쁨·실패·다른 메뉴 → Bad, 마감까지 못 받음 → Expired(손님 이탈 1회 감점, 효과는 Bad 와 같음). 받은 뒤(마감 넘김 포함) 인플루언서가 결과에 맞는 소감을 선택지 없는 대화창으로 말한다(`EventDialog.Show` 에 선택 콜백 null). 영업 종료로 넘긴 경우에는 대화창 없이 처리한다.
5. **평판은 그날 정산에 더하고, 손님 수는 다음 DAY 부터 바뀐다.** 결과별 평판 변동을 `DayResult.eventReputationChange` 에 더하고 영업 종료 때 만족도 평균 평판 변동과 합친다. 손님 수 배율은 `SaveData.visitorRate` 에 곱해 저장하고(0.5~2 범위), `CustomerManager` 는 영업 시작 때 이 값을 읽어 입장 간격을 배율로 나눈다(영상이 올라간 다음 날부터 효과).
6. **거절하면 효과가 없다.** 평판·손님 수 모두 그대로다.
7. 인플루언서 주문도 단체 주문처럼 **선입선출 감점에서 빠지고(`Order.IsEvent`), 매장 컵 수를 줄이지 않는다.**
8. 선택 결과는 `SaveData.choices` 에 `day6_influencer` = `accept` / `decline`, 촬영 결과는 `day6_influencer_result` = `great` / `good` / `bad` / `expired` 로 남는다 (SFR-071, 엔딩·후속 스토리에서 쓸 수 있음).
9. 설정(DAY, 요청·마감 시각, 대표 메뉴, 결과별 평판 변동·손님 수 배율)은 `GameBalance.influencerEvents` 의 `InfluencerEvent` 목록에 둔다.

## 검토한 대안

- 플레이어가 여러 메뉴 중 대표 메뉴를 직접 고름: "추천" 에 더 가깝지만 대화창에 메뉴 선택 UI와 버튼 아트가 새로 필요해 고르지 않았다. 나중에 필요하면 `InfluencerEvent.menuId` 대신 후보 목록을 두고 대화창 선택지를 늘리면 된다.
- 인플루언서가 실제 손님처럼 들어와 줄 서고 자리에 앉음: 손님 동선·좌석 처리 변경이 커서 단체 주문과 같은 "픽업대 앞 대기" 로 했다.
- 손님 수 변화를 그날 남은 영업에 바로 적용: 영상이 공개되는 시점을 생각하면 다음 날부터가 자연스럽고, 같은 날 효과는 체감하기 어렵다.
- 새 안내 문구(Toast) 이미지로 결과 표시: 글자 이미지 생성이 필요하고 정보량이 적어, 기존 대화창으로 소감을 보여 주기로 했다.

## 결과

- DAY 6 영업 중 한 번, 대표 메뉴 한 잔을 제대로 만드는 짧은 목표가 생기고 그 결과가 이후 DAY 의 손님 수와 평판(엔딩 조건)에 이어진다.
- `GroupDeadline` 이 단체 주문·인플루언서 주문을 함께 표시한다. 영수증 이벤트 줄의 글자 이미지(`Label`)는 단체 주문일 때만 켜진다.
- 이벤트 대화 중에는 진동벨 호출 창의 키 입력도 막는다 (포스기 Enter 와 같음).
- Cafe 씬을 다시 빌드해야 `InfluencerManager` 가 씬에 들어간다 (`CafeTime/...` 씬 빌더).
- 수치는 docs/GAME_DATA.md 9장에 있고 모두 임시다. 이미 있는 `GameBalance.asset` 에는 새 필드 기본값이 적용되고 Inspector 에서 조절한다. 기존 저장 파일에는 `visitorRate` 가 없어 1(변화 없음)로 읽힌다.
