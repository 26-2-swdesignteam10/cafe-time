# ADR-0030: 베이커리는 손님 대사를 보고 포스기에 직접 입력한다

- 상태: 승인
- 날짜: 2026-11-12
- 관련 명세: SFR-026, SFR-027, SFR-056

## 맥락

사용자는 베이커리를 포스기에 바로 추가하지 말고, 원래처럼 손님이 품목을 말하며 결제를 요청하면 플레이어가 직접 포스기에 추가하는 방식을 원했다. ADR-0029의 자동 등록·수량 고정 결정을 변경한다.

## 결정

- 손님이 진열장에서 직접 가져오는 베이커리 8종과 재고 차감 시점은 유지한다.
- 손님은 실제로 가져온 베이커리의 이름과 수량을 대사로 알려 주며 결제를 요청한다. 예: “가져온 샌드위치 하나 결제해 주세요.”
- 포스기는 빈 목록으로 열리고, 음료와 베이커리를 모두 플레이어가 직접 입력한다.
- 베이커리 메뉴 버튼과 수량 증감·삭제·취소를 활성화한다. 목록을 취소하거나 창을 다시 열면 자동 복원하지 않는다.
- 결제 금액과 영수증은 플레이어가 입력한 품목·수량을 따른다. 잘못 입력하거나 누락한 베이커리를 실물 내역으로 자동 보정하지 않는다. 기존 음료 오입력과 같은 입력 규칙이다.
- 베이커리 실물 재고는 집는 순간에만 차감한다. 포스기 입력·결제는 재고를 추가 차감하거나 복구하지 않는다. 이탈·환불 시에는 실제로 집었던 수량을 복구한다.
- 베이커리는 제조·픽업대 서빙 대상에서 계속 제외한다. 별도 계산 오입력 감점은 추가하지 않는다.

## 검토한 대안

- 베이커리 자동 등록·고정: 사용자 요청에 따라 폐기한다.
- 포스기 입력을 가져온 품목·수량으로 강제 보정: 직접 주문을 듣고 입력하는 기존 플레이 방식과 달라 채택하지 않는다.

## 결과

ADR-0029의 포스기 자동 등록·수량 고정 부분만 대체한다. 가격·품목·손님 동선·베이커리 서빙 제외·환불 규칙은 유지한다. 씬·프리팹 재빌드는 필요하지 않다.

## Unity 확인 절차

1. 베이커리를 집은 손님의 주문을 받고, 대사에 실제 품목·수량과 “결제해 주세요”가 표시되는지 확인한다.
2. 포스기가 빈 목록으로 열리는지, 디저트 탭에서 8종을 직접 추가하고 수량 증감·삭제·전체 취소할 수 있는지 확인한다.
3. 음료·베이커리를 입력해 합계와 영수증이 입력 내역과 일치하는지 확인한다. 잘못된 품목·수량과 누락을 자동 보정하지 않는지도 확인한다.
4. 결제 뒤 재고가 중복 차감되지 않고 픽업대에는 음료만 표시되는지 확인한다. 이탈·환불 시 포스기 입력 수량이 아니라 실제로 집었던 수량이 복구되는지 확인한다.
