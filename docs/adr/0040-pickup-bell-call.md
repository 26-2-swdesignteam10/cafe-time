# ADR-0040: 픽업대 진동벨 번호 호출로 서빙

- 상태: 승인
- 날짜: 2026-11-18
- 관련 명세: SFR-056, SFR-058

## 맥락

픽업대는 트레이마다 서빙 버튼이 있어 누르면 앉아 있는 손님이 바로 음료를 받았다 (ADR-0018). 2026-11-18 사용자 요청: "픽업대에서 진동벨 호출 모달창도 따로 만들어서 그 모달창으로 넘어가면 계산기 느낌에서의 번호타자판이 나오고 호출이 되면 그때 손님이 오도록". 인터뷰에서 사용자가 정한 것: 없는 번호를 누르면 안내만 한다, 호출된 일행 중 1명이 픽업대로 와서 받아 간다.

## 결정

- 트레이별 서빙 버튼을 없애고, 픽업대 창에 진동벨 호출 버튼 1개를 둔다. 누르면 계산기형 번호 키패드 창(`BellCallScreen`)이 열린다. 키보드 숫자·Backspace·Enter 도 받는다.
- 번호를 호출하면 그 주문 트레이가 고정되고("호출됨"), 일행 중 1명이 좌석에서 픽업대 앞(`CustomerManager.pickupPoint`)으로 걸어온다. 도착하면 호출 때 트레이에 있던 물건을 받아(`Serve`) 자리로 돌아가 앉고, 일행이 마시기 시작한다.
- 걸어오는 동안(`CustomerParty.State.ToPickup`) 기다림 게이지는 멈추고, 만족도의 대기 시간은 호출 시점까지로 계산한다.
- 없는 번호, 빈 트레이, 이미 호출한 번호는 키패드 화면에 안내 글만 띄우고 감점하지 않는다.
- 선입선출 위반 감점(ADR-0022)은 호출 시점에 판정한다 (먼저 들어온 주문 중 아직 호출하지 않은 것이 있으면 감점).
- 호출 입구를 픽업대 창의 버튼 1개로 한 것과, 호출 즉시 트레이를 고정하는 것은 에이전트가 정한 기본안이다.

## 검토한 대안

- 트레이마다 호출 버튼: 번호를 직접 입력하는 진동벨 느낌이 약해 기본안에서 제외.
- 잘못 호출하면 감점: 사용자가 안내만 하는 쪽을 골랐다.
- 일행 전체가 오거나 걷는 연출 없이 즉시 받음: 사용자가 1명이 받아 가는 쪽을 골랐다.

## 결과

- 서빙에 번호 확인 단계와 손님 이동 시간이 생긴다. 걸어오는 시간은 만족도에 들어가지 않는다.
- 영업 종료 때 받으러 오던 손님은 다른 미서빙 손님처럼 환불·이탈 처리된다.
- ADR-0018 의 "서빙 버튼으로 내보낸다" 부분을 대체한다.
