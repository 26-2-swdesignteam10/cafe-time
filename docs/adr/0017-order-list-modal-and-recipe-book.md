# ADR-0017: 상단 주문표를 주문 내역 버튼·모달로 바꾸고 레시피북을 둔다

- 상태: 대체됨 (ADR-0018 픽업대 배정 부분, ADR-0019 레시피 카드 배치 부분)
- 날짜: 2026-11-09
- 관련 명세: SFR-013, SFR-051, SFR-056

## 맥락

영업 HUD 위쪽에 주문표(ticket)를 가로로 나열했는데, 주문 줄이 길어지거나 주문이 많아지면 주문표가 넘쳐 화면이 깨졌다.
사용자는 "주문 내역 버튼"만 HUD 에 두고, 누르면 영수증이 나열된 모달 창을 여는 구조로 바꾸기로 했다.
게임 안에 레시피를 확인할 곳이 없어서 레시피북 버튼도 함께 두기로 했다.

## 결정

- HUD 오른쪽 위에 **주문 내역** 버튼과 **레시피** 버튼을 둔다. 주문 내역 버튼에는 대기 중인 주문 수 배지를 표시한다 (0이면 숨김). 단축키는 두지 않는다.
- **주문 내역 창**(`OrdersScreen`, `Popup`): 대기 중인 주문을 영수증(`TicketView`)으로 가로로 나열하고, 넘치면 가로 스크롤한다. 영수증에는 주문 번호, 메뉴 줄(HOT/ICE, 수량), 결제 금액, 픽업대에 배정된 개수를 표시하고, 높이는 메뉴 줄 수에 맞춰 늘어난다.
- **픽업대 배정**(SFR-056): 픽업대 화면이 열린 상태에서 주문 내역 창의 영수증을 누르면 선택한 물건을 그 주문에 배정하고 창이 닫힌다. 배정은 `OrdersScreen` 이 `PickupScreen.TryAssign` 을 직접 부른다 (`OrderBoard.TicketClicked` 이벤트는 없앤다).
- **레시피북 창**(`RecipeBookScreen`, `Popup`): 위쪽 분류 탭(커피·음료·스무디), 왼쪽 메뉴 목록, 오른쪽에 HOT·ICE 레시피 카드. 재료는 아이콘 + 이름 + 양으로 표시하고, 내용은 `GameBalance` 의 메뉴·레시피 데이터를 그대로 읽는다. 디저트는 레시피가 없어 탭에 넣지 않는다.
- 두 창이 열려 있어도 게임 시간은 흐르고, 다른 팝업처럼 이동만 막히며 ESC 로 닫힌다.

## 검토한 대안

- 주문표를 그대로 두고 크기만 줄이기: 주문 수와 줄 수가 늘면 같은 문제가 다시 생긴다.
- 픽업대 화면 안에 주문 선택 목록을 따로 두기: 주문 정보를 두 곳에서 관리하게 된다. 사용자가 모달의 영수증을 눌러 배정하는 방식을 골랐다.
- 영수증 메뉴 줄마다 레시피 버튼 / 영수증에 메뉴 그림만 붙이기: 사용자가 HUD 의 별도 레시피북 버튼을 골랐다.

## 결과

- 주문 수·줄 수와 관계없이 HUD 가 깨지지 않는다.
- 주문을 보려면 버튼을 한 번 눌러야 한다. 대신 배지로 대기 주문 수를 항상 보여 준다.
- 픽업대 배정은 "물건을 픽업대에 놓기 → 주문 내역 열기 → 영수증 누르기" 순서가 된다.
- 레시피북은 데이터를 그대로 보여 주므로, 레시피를 바꾸면 `GameBalance` 만 고치면 된다. 샷·얼음·물(`RecipeKeys`)의 표시 이름과 단위는 `RecipeBookScreen` 에 있다.
