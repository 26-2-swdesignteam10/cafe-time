# ADR-0004: 모든 팝업·기기 화면은 Popup 베이스 클래스를 상속한다

- 상태: 승인
- 날짜: 2026-10-29
- 관련 명세: SFR-015, SFR-020, SFR-023, SFR-029 외 기기 화면 전반

## 맥락

명세에 반복되는 규칙이 있다.

- "X 버튼 또는 ESC 키 입력 시 화면을 닫고 맵으로 복귀" (기기 화면 전체)
- "UI가 열려 있으면 이동·상호작용 입력 무시" (SFR-015, 020)
- "UI가 열려 있으면 ESC는 해당 화면을 닫는 데 사용, 아니면 일시정지 메뉴" (SFR-023)

화면마다 따로 구현하면 동작이 어긋난다.

## 결정

`CafeTime.UI.Popup` 을 모든 팝업·기기 화면의 부모로 쓴다.

- 열린 팝업을 열린 순서대로 정적 리스트로 관리한다 (`OnEnable`/`OnDisable`).
- `Popup.AnyOpen`: UI가 하나라도 열려 있는지
- `Popup.CloseTop()`: 가장 위의 팝업을 닫고, 닫을 게 없으면 `false` → ESC 처리에서 일시정지 메뉴를 열지 판단하는 데 사용
- 닫을 때 처리가 필요하면 `Close()` 를 override 한다.

## 검토한 대안

- UI 매니저 싱글톤이 모든 창을 등록·관리: 씬마다 매니저 배치가 필요하고, 프리팹을 단독으로 테스트하기 어렵다.

## 결과

- 플레이어 이동·상호작용 코드는 `Popup.AnyOpen` 만 확인하면 된다.
- 정적 상태이므로 도메인 리로드를 끈 경우를 대비해 `RuntimeInitializeOnLoadMethod` 로 초기화한다.
- 팝업이 아닌 상시 UI(HUD 등)는 `Popup` 을 상속하지 않는다.
