# ADR-0014: 기기 화면, 물건 모델, 레시피 판정 구조

- 상태: 제안
- 날짜: 2026-11-04
- 관련 명세: SFR-021~023, 028~068, 073

## 맥락

ADR-0013 은 영업 루프만 만들고, 음료 제조는 메뉴를 누르면 완성 음료가 손에 들리는 임시 제조실로 대신했다.
이번에는 사용자 요청("팀원이 만든 것(스토리, SFR-007~009)을 제외한 전체를 개발한 뒤 하나씩 테스트")에 따라 실제 기기 화면 전체와 득점·엔딩을 만든다.
기기는 9종이고 서로 물건(잔, 샷 컵, 스쿱, 쟁반 물건)을 주고받는다. 기기 화면을 닫아도 진행 중인 작업(추출, 제빙, 건조)은 계속돼야 한다(SFR-022).
명세에 정량이 없는 값(레시피, 허용 오차, 기기 수치, 점수, 엔딩 기준)이 많아 임시값이 필요하다.

## 결정

1. **물건 모델**: 손에 드는 것은 모두 `HeldItem` 상속 클래스다 (`Cup`, `ShotGlass`, `IceScoop`, `DessertItem`, `Towel`).
   잔은 내용물(`Mixture`, 재료 키 → 양)을 가지고, '완성'을 누르면 메뉴·등급이 정해진다. 서빙(픽업대)에는 `Servable` 인 물건만 놓을 수 있다.
2. **기기 상태와 화면 분리**: 기기 상태는 항상 켜져 있는 `Business` 오브젝트의 컴포넌트(`CupShelf`, `EspressoMachine`(ADR-0015), `IceMaker`, `WaterDispenser`, `DrinkStation`, `Blender`, `TrayReturn`, `DishStation`, `CleaningManager`)에 두고,
   기기 화면(`StationScreen` 상속 Popup)은 상태를 그리기만 한다. 화면을 닫아도 타이머는 `GameClock.Delta` 로 계속 흐르고, 맵의 `WorkStatusIcon` 이 게이지·완료 아이콘을 보여 준다.
3. **레시피 판정**: 잔에 든 재료 **키 집합**이 정확히 같은 레시피를 그 메뉴로 인식한다. 맞는 레시피가 없으면 '실패한 음료'.
   재료별 상대 오차 중 최댓값으로 완벽/좋음/나쁨을 정하고, 잔 종류(HOT=도자기, ICE=플라스틱)가 틀리면 '나쁨'. 레시피는 `GameBalance.recipes`.
4. **조작 방식**: 손 칸 ↔ 기기 화면은 끌어다 놓기(`DropZone`), 또는 손 칸을 클릭해 선택한 뒤 자리를 클릭. 기기 안 물건은 `DragItem`, 탬퍼·수세미는 끄는 방향만 쓰는 `DragMotion`, 우유·탄산수는 누르고 있는 동안 붓는 `HoldButton`.
5. **도구 내려놓기**: 빈 샷 컵·스쿱·행주를 손 칸의 '버리기'로 처리하면 버리지 않고 원래 자리로 돌려놓는다 (감점 없음). 잔·디저트를 버리면 설거지 대기로 가고 '버린 재료·음료' 감점.
6. **잔·접시 수량**은 저장하지 않고 매일 아침 모두 깨끗한 상태로 시작한다. 재료 남은 양 %(SFR-049)의 기준은 그날 영업 시작 때 재고.
7. **씬 흐름**: Cafe → **Score**(득점 결과, SFR-067) → Settlement → (DAY 15 또는 임대료 부족) **Ending**(SFR-073). 엔딩 종류는 정산이 `Endings.Pending` 에 정하고, 엔딩 화면은 저장 데이터를 지운다.
   하루 최고 점수(`SaveData.bestScore`)는 정산 때 저장한다(그날 영업은 정산 전까지 저장되지 않음, SFR-071).
8. **일시정지(SFR-023)**: ESC 로 연 일시정지 메뉴가 열려 있는 동안 `GameClock.Paused` + `Time.timeScale = 0`. 설정·확인 창은 타이틀과 같은 프리팹.
9. 임시 제조실(`TempDrinkMakerScreen`)과 '준비 중' 창(`StationScreenPlaceholder`), 그 그림은 삭제한다.
10. 랭킹 보기 버튼(SFR-067)과 랭킹 서버(SFR-069, 070)는 이번 범위에서 제외한다 (사용자 결정).

수치는 모두 임시값으로 [GAME_DATA.md](../GAME_DATA.md) 에 `임시` 로 기록했다.

## 검토한 대안

- 기기 상태를 각 화면(Popup)에 두기: 화면이 꺼지면 `Update` 가 돌지 않아 추출·제빙·건조가 멈추므로 채택하지 않음.
- 레시피를 메뉴 선택 후 만들기(먼저 메뉴를 고르고 재료 넣기): 명세(SFR-051)는 완성 시 결과로 메뉴를 판정하므로 채택하지 않음.
- 도구 전용 '내려놓기' 버튼: 손 칸 메뉴 그림이 하나 더 필요해서 우선 '버리기'를 재사용. 테스트 후 헷갈리면 라벨 이미지를 추가한다.
- 잔 수량을 저장 데이터에 두기: 정산 후 다음 날로 넘어갈 때 설거지가 남은 상태를 이어 가야 하는데 명세에 근거가 없어 채택하지 않음.

## 결과

- 기기 화면을 닫아도 작업이 이어지고, 맵에서 진행 상태를 볼 수 있다.
- 새 메뉴는 `GameBalance` 에 메뉴 + 레시피만 추가하면 판정된다. 재료 종류가 같은 두 레시피는 구별되지 않으므로, 레시피를 추가할 때 재료 키 집합이 겹치지 않게 한다.
- 기기 화면 배치는 `Editor/StationUiBuilder.cs`, 씬 연결은 `CafeSceneBuilder` 가 만든다 (ADR-0006). 그림 규격은 `Art/UI/<기기>/Generation.md`.
- ADR-0013 의 '임시 제조실' 부분은 이 ADR 로 대체된다 (ADR-0013 의 영업 루프 구조는 그대로 유효하므로 ADR-0013 상태는 제안으로 둔다).
