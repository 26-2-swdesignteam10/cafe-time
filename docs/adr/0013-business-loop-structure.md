# ADR-0013: 영업 루프 구조와 임시 제조실

- 상태: 제안
- 날짜: 2026-11-03
- 관련 명세: SFR-013, 014, 021, 024~027, 056~058, 072

## 맥락

오픈 준비(SFR-010)와 하루 정산(SFR-071)은 있지만, 그 사이의 영업(손님 입장 → 주문 → 서빙 → 퇴장)이 없어 하루가 실제로 돌지 않았다.
음료 제조 기기(SFR-028~055)는 분량이 커서 나중에 기기별로 나눠 만들 예정이지만, 영업 흐름은 지금 확인할 수 있어야 한다.
사용자는 양손 인벤토리(SFR-021)까지 이번에 같이 만들어 실제에 가까운 흐름으로 테스트하기로 했다.

## 결정

Cafe 씬에 아래 구조로 영업 루프를 만든다 (`Scripts/Cafe/`).

| 클래스 | 역할 |
|---|---|
| `GameClock` | 게임 시간 09:00~21:00, 20:00 입장 마감, 21:00 종료. 손님 타이머는 모두 `GameClock.Delta` 를 써서 일시정지(SFR-023) 때 같이 멈춘다 |
| `CustomerManager` | 일행 입장·줄·주문·서빙·환불·퇴장. 길찾기 없이 정해 둔 통로(문 → 가운데 세로 통로 → 가로 통로)를 따라 꺾은선으로 걷는다 |
| `OrderBoard` | 등록된 주문 목록. 상단 주문표와 픽업대 배정이 이 목록을 본다 |
| `HandInventory` | 양손 2칸. 기기 화면이 물건을 넣고, 픽업대가 꺼낸다 |
| `BusinessDay` | 종료 처리, 평판 변동 계산 후 하루 정산으로 이동 |

- 손님이 원한 메뉴(`CustomerParty.Wanted`)와 플레이어가 포스기에 입력한 주문(`Order.Lines`)을 따로 둔다. 잘못 입력해도 그대로 등록되고, 만족도는 원한 메뉴와 받은 물건을 비교한다 (SFR-026).
- 결제 금액과 팁은 그 자리에서 보유 자금에 더하고, `DayResult` 에는 기록만 남긴다. 음료를 못 받고 떠나면 환불한다.
- **임시 제조실**: 음료 제조 기기가 생기기 전까지 `음료 제조실`·`쉐이크 제조실` 에서 메뉴를 누르면 '완벽' 등급 음료를 바로 손에 든다 (`TempDrinkMakerScreen`). 재료는 차감하지 않는다. 제조 기기가 구현되면 이 화면을 교체하고 클래스를 삭제한다.
- 득점 결과 화면(SFR-067)이 생기기 전까지는 영업 종료 후 바로 하루 정산으로 간다.
- 만족도 계산식, 팁, 평판 변동, 손님 입장 간격·인내심 등 "추후 결정" 수치는 `GameBalance` 의 임시값으로 둔다 (docs/GAME_DATA.md).

## 검토한 대안

- 픽업대에서 E를 누르면 바로 서빙(인벤토리 없음): 더 빨리 만들 수 있지만 SFR-056의 "인벤토리에서 픽업대로 드래그" 흐름을 확인할 수 없어 사용자가 양손 인벤토리까지 만들기로 함
- NavMesh 등 길찾기: 맵이 고정이고 손님 동선이 단순해 필요 없음. 기기 배치 변경(SFR-011)으로 동선이 바뀌면 다시 검토
- 손님을 프리팹으로 만들기: 외형 4종 × 스프라이트 교체뿐이라 코드로 생성. 애니메이션이 생기면 프리팹으로 바꾼다

## 결과

- 오픈 준비 → 영업 → 하루 정산이 한 바퀴 돈다.
- 제조 기기를 만드는 사람은 완성 음료를 `HandInventory.TryAdd(new HeldItem(menu, temperature, grade))` 로 손에 넣으면 나머지(픽업대·만족도·팁)가 그대로 동작한다.
- 퇴식구 쟁반 반납(SFR-057, 060), 설거지 대기(SFR-021), 재료 차감은 해당 기능을 만들 때 추가한다.
