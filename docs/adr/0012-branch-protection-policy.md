# ADR-0012: main 브랜치는 PR 필수, 리뷰 승인은 선택, Repo check는 필수로 한다

- 상태: 승인
- 날짜: 2026-11-02

## 맥락

처음에는 `main` 브랜치 보호에 "PR + 리뷰 승인 1명 + Repo check 통과"를 걸었다.
팀원 수가 적고 각자 맡은 기능을 따로 개발해서, 승인을 기다리는 동안 작업이 자주 멈췄다.
반면 `main` 에 직접 push 하거나 `.meta` 가 빠진 커밋이 들어가면 다른 팀원의 프로젝트가 깨진다.

## 결정

GitHub `main` 브랜치 보호를 다음과 같이 설정한다.

| 항목 | 설정 |
|---|---|
| PR을 통한 merge | 필수 (직접 push 불가) |
| 리뷰 승인 수 | 0 (리뷰는 권장, 필수 아님) |
| 필수 상태 검사 | `Repo check` |
| Unity build | 필수 아님. 라이선스 Secrets가 등록되기 전까지 자동으로 건너뜀 |

리뷰를 받는 기준은 [CONTRIBUTING](../CONTRIBUTING.md) 2장에 둔다 (다른 사람 기능·공통 코드·씬을 건드린 PR, `제안` ADR이 있는 PR).

## 검토한 대안

- 승인 1명 유지: 품질 확인은 확실하지만 리뷰 대기로 작업이 막힌다.
- 브랜치 보호 제거: 가장 빠르지만 직접 push와 검사 실패 커밋을 막을 수 없다.
- Repo check를 필수에서 제외: 7초 정도로 가벼운 검사이고, `.meta` 누락처럼 다른 팀원에게 피해를 주는 실수를 잡으므로 유지한다.
- Unity build 활성화: 1회 15~30분, Actions 무료 사용량을 많이 쓴다. 릴리즈(SFR-074) 전에 다시 검토한다.

## 결과

- 작성자가 CI 통과 후 바로 merge 할 수 있다.
- 리뷰 없이 들어간 변경의 문제는 이후 PR에서 고친다. 리뷰 코멘트가 달렸다면 반영하거나 답을 단 뒤 merge 한다.
- 브랜치 보호 설정을 바꾸면 새 ADR로 기록한다.
