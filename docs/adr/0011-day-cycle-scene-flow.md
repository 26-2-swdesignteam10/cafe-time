# ADR-0011: 하루 사이클의 씬 흐름과 영업 결과 전달 방식

- 상태: 제안
- 날짜: 2026-11-02
- 관련 명세: SFR-002, SFR-007, SFR-009, SFR-010, SFR-014, SFR-067, SFR-071, SFR-073

## 맥락

하루는 "스토리 → 오픈 준비 → 영업 → 득점 결과 → 하루 정산 → 다음 날" 순서로 진행된다.
각 단계는 다른 팀원이 다른 브랜치에서 개발하고 있어, 서로의 클래스를 직접 참조하면 머지 순서에 묶인다 (ADR-0003).
또 메인 스토리는 일부 DAY에만 있다(SFR-009).

## 결정

씬 흐름:

```
Title ─(새 게임)──→ Story(DAY1 프롤로그) ─→ OpenPrep ─→ Cafe(영업) ─→ Result(득점) ─→ Settlement(정산)
Title ─(이어하기)─→ OpenPrep                   ↑                                          │
                                                └── Story(다음 DAY, 스토리 없으면 즉시 통과) ←┘
Settlement ─(임대료 부족 / DAY15 정산 후)─→ Ending
```

- 정산 화면은 다음 DAY로 갈 때 **항상 Story 씬을 로드**한다. Story 씬은 해당 DAY에 스토리가 없으면 바로 OpenPrep으로 넘긴다. 따라서 정산 화면은 어떤 DAY에 스토리가 있는지 알 필요가 없다.
- 영업 결과(방문 손님 수, 판매 음료 수, 오늘 수익, 팁, 평판 변동 등)는 Core의 `DayResult` 데이터로 넘긴다. 영업 씬이 채우고 득점·정산 씬이 읽는다.
- 대상 씬이 아직 없으면(다른 브랜치에서 개발 중) 다음 단계로 건너뛰어 사이클 전체를 테스트할 수 있게 한다. `SceneLoader.LoadFirstAvailable(우선 씬, 대체 씬)` 으로 처리한다.

  | 이동 | 우선 씬 | 없을 때 |
  |---|---|---|
  | 새 게임 시작 | Story | OpenPrep |
  | 영업 시작 | Cafe | Settlement (빈 `DayResult`) |
  | 정산 후 다음 날 | Story | OpenPrep |
  | 임대료 부족 / DAY15 정산 후 | Ending | Title |

- `DayResult.StartNewDay()` 는 오픈 준비에서 영업을 시작할 때 호출한다.
- 씬을 에디터에서 바로 Play 하면(`SaveSystem.Current` 가 없으면) `SaveSystem.EnsureCurrentForPreview()` 가 시작 자금으로 임시 데이터를 만든다. 임시 데이터는 파일에 저장하지 않는다.
- 임대료를 낼 수 없으면 저장하지 않고 엔딩으로 간다 (저장 파일은 직전 DAY 정산 상태로 남음).

## 검토한 대안

- 정산 화면이 `StoryData.HasStory(day)` 를 직접 호출: Story 기능을 참조하게 되어 기능 간 의존이 생긴다.
- 씬 전환 없이 한 씬에서 패널만 전환: 씬 하나를 여러 사람이 동시에 수정하게 된다 (ADR-0007).

## 결과

- 스토리가 없는 날에는 Story 씬이 잠깐 로드됐다가 넘어간다. 화면 깜빡임이 거슬리면 Story 씬에서 첫 프레임 전에 넘기도록 개선한다.
- 영업 기능을 만드는 팀원은 `DayResult` 를 채우는 책임을 진다.
- 엔딩 씬을 만들 때, 파산 후 이어하기를 허용할지(현재는 직전 DAY부터 다시 가능)와 DAY15 이후 저장 데이터(day = 16)로 이어하기를 눌렀을 때의 처리를 정해야 한다.
