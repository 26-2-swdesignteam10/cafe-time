# ADR-0053: 서빙한 음료·베이커리를 맵의 픽업대 카운터와 손님 테이블 위에 그림으로 보여 준다

- 상태: 승인
- 날짜: 2026-11-24
- 관련 명세: SFR-024, SFR-056, SFR-057

## 맥락

지금까지 픽업대 트레이에 음료를 놓아도 맵에는 아무 변화가 없었다. 손님이 받아 간 뒤에도 테이블에는 음식이 보이지 않았다. 사용자가 2026-11-24에 두 가지를 요청했다. "픽업대에 실제 음료가 완성되면 그 음료와 디저트가 픽업대에 보이도록 해 줘. (디저트는 자동 배치됨)", "손님이 음료를 가져가고 테이블에 앉으면 해당 음료와 디저트를 먹는 걸로 해 줘." 표시 위치는 사용자가 '맵의 픽업대 카운터'로 정했다.

## 결정

- 맵의 픽업대 카운터(`PickupCounterView`): 트레이에 놓은 음료를 주문이 들어온 순서대로 카운터 위에 늘어놓는다. 그 주문 손님이 진열대에서 집어 온 베이커리는 음료를 하나라도 놓으면 자동으로 같이 놓인다. 손님이 받아 가 주문이 사라지면 카운터에서도 없어진다.
- 손님 테이블(`CafeTable`): 일행이 받은 음료와 베이커리를 일행이 모두 자리에 앉았을 때 자리마다 나눠 앞에 놓는다. 머무는 동안(`StayDuration`) 5번 나눠 먹는다. 한 입마다 베이커리가 줄어들고, 음료는 들었다 내려놓이고, 손님은 살짝 들썩인다. 떠날 때 테이블의 음식은 없어지고, 쟁반 반납 규칙은 그대로다.
- 그림은 손 칸·픽업대 창과 같은 물건 아이콘(메뉴 그림, 베이커리 재료 아이콘)을 크기만 줄여 쓴다. 새 그림은 만들지 않는다.
- 앞뒤 정렬: 물건은 가구 기준점 바로 앞에 SortingGroup 층으로 묶는다. 그래서 가구와 가구 뒤의 사람보다는 앞, 가구 앞에 선 사람보다는 뒤에 그려진다.
- 놓는 위치·크기·먹는 횟수는 `PickupCounterView`, `CafeTable`의 `[SerializeField]`로 둔다.

## 검토한 대안

- 픽업대 창(팝업) 트레이에만 베이커리를 표시: 사용자가 맵 카운터를 골랐다.
- 다 먹은 잔·반쯤 먹은 빵 그림을 새로 그리기: 아이콘 축소·들썩임 연출로 먼저 확인하고, 필요하면 나중에 Codex로 그림을 추가한다.

## 결과

- 맵만 보고도 어떤 주문이 준비됐는지, 손님이 무엇을 먹고 있는지 알 수 있다.
- 아이콘 그림은 원래 UI용이라 맵 도트와 해상도가 다르다. 어색하면 맵 전용 작은 그림을 따로 만든다.
- 베이커리는 셀프서비스 포장이라 설거지 접시를 만들지 않는 규칙(ADR-0030)은 그대로다. 테이블에서 먹어도 쟁반에 접시가 추가되지 않는다.
