# ADR-0043: 샷이 빠진 커피 레시피는 에셋 동기화 때 코드 레시피로 복구한다

- 상태: 제안
- 날짜: 2026-11-19
- 관련 명세: SFR-048, SFR-051
- 관련 ADR: ADR-0038(메뉴 개편·에셋 동기화)

## 맥락

메뉴 개편 커밋(c1155f5, PR #18)에서 `Resources/GameBalance.asset` 의 커피 레시피 12개(아메리카노·카페라떼·바닐라라떼·카라멜마키아토·헤이즐넛라떼·카페모카의 HOT/ICE)가 `shot` 1회 대신 `cheong_strawberry` 40g 으로 저장됐다. 코드의 기본 레시피(`GameBalance.DefaultRecipes`)는 샷으로 맞게 되어 있다.

레시피는 재료 구성으로 메뉴를 알아보고 정량으로 등급을 매기므로(SFR-051), 이 상태에서는 레시피북에 "딸기청 40g" 이 보이고 샷을 넣은 정상 커피가 실패로 판정된다. 2026-11-19 사용자가 레시피북에서 발견하고 이 브랜치에서 고치라고 했다.

ADR-0038 의 `EnsureCatalog` 는 이미 있는 레시피를 정량까지 그대로 보존하므로 저절로 고쳐지지 않는다. `.asset` YAML 은 직접 편집하지 않는다(AGENTS.md).

## 결정

- `GameBalance.EnsureCatalog` 에서 코드 레시피에는 샷이 있는데 에셋 레시피에 샷이 없으면, 그 레시피를 코드 레시피로 통째로 바꾼다.
- 그 밖의 레시피는 지금처럼 보존한다 (Inspector 에서 조절한 정량 유지).
- `EnsureCatalog` 는 에셋이 로드될 때마다 실행되므로 실행 중에는 바로 맞는 레시피를 쓴다. 에셋 파일은 `CafeTime > Create Game Balance` 를 실행하면 저장된다.

## 검토한 대안

- 재료 구성이 코드와 다른 모든 레시피를 되돌림: Inspector 에서 일부러 바꾼 레시피까지 덮어쓸 수 있어 고르지 않았다.
- 레시피 전체를 코드 기본값으로 초기화하는 메뉴: 조절한 정량이 모두 사라진다.
- `.asset` 직접 수정: 규칙상 하지 않는다.

## 결과

- 커피 레시피 12개가 샷 1회로 돌아온다. 정량도 코드 기본값이 된다.
- 앞으로 샷이 필요한 레시피에서 샷을 빼려면 코드의 기본 레시피도 같이 바꿔야 한다.
