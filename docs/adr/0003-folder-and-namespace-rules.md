# ADR-0003: 기능별 폴더 + 폴더 이름 = namespace, Core는 단방향 의존

- 상태: 승인
- 날짜: 2026-10-29

## 맥락

명세 항목이 70개가 넘고 팀원이 기능 단위로 나눠 개발한다.
공통 코드(저장, 씬 이동)가 특정 기능 코드를 참조하기 시작하면 기능 하나를 고칠 때 전체가 깨진다.

## 결정

- 우리가 만든 파일은 모두 `Assets/_Project/` 아래에 둔다 (외부 에셋과 분리).
- 스크립트는 `Scripts/<기능>/` 에 두고 namespace를 `CafeTime.<기능>` 으로 맞춘다.
- `Scripts/Core/` 는 게임 전체 공통 코드이며 **다른 기능 namespace를 `using` 하지 않는다.** (기능 → Core 방향으로만 의존)
- 클래스 하나 = 파일 하나, 파일 이름 = 클래스 이름.
- 위 규칙은 CI(`.github/scripts/check-repo.sh`)에서 자동 검사한다.

## 검토한 대안

- Assembly Definition(asmdef)으로 의존 방향 강제: 더 확실하지만 초기 설정 부담이 크다. 프로젝트 규모가 커지면 다시 검토한다.
- 타입별 폴더(Scripts/Managers, Scripts/UI ...): 한 기능의 코드가 여러 폴더로 흩어져 담당자 구분이 어렵다.

## 결과

- 기능 간에 데이터를 주고받아야 하면 Core에 데이터 타입을 두고 양쪽이 Core를 참조한다.
- 아직 머지되지 않은 다른 기능의 클래스를 직접 참조하지 않는다.
