# ADR-0020: 하루 영업을 약 10분으로 줄이고 DAY별 난이도 표를 둔다

- 상태: 대체됨 (ADR-0021, 하루 시간 부분)
- 날짜: 2026-11-12
- 관련 명세: SFR-014, SFR-024, SFR-025, SFR-057

## 맥락

플레이 테스트에서 사용자가 "DAY 초반치고는 난이도가 너무 높다"고 했다 (2026-11-12).

- 명세서 SFR-014 는 실제 2분 = 게임 1시간(하루 약 24분)으로 정해 두었다. 하루가 길고, 손님 입장 간격이 실제 초 단위라서 하루에 오는 손님도 많았다.
- DAY에 따라 바뀌는 것은 입장 간격(매일 ×0.95)뿐이었다. DAY 1부터 1~4명 일행과 같은 인내심이 그대로 적용됐다.

## 결정

1. **하루 약 10분**: 게임 1시간 = 실제 50초로 바꾼다 (`GameBalance.secondsPerGameHour`). 영업 09:00~21:00 = 실제 600초. 명세서 SFR-014 의 "2분"을 사용자 요청으로 바꾼다.
2. **DAY별 난이도 표**: `GameBalance.difficultyByDay` 에 DAY 1~15 한 줄씩(`Core/DayDifficulty`) 둔다. 한 줄은 손님 입장 간격(최소~최대), 일행 인원 1~4명 가중치, 주문 대기 인내심, 음료 대기 인내심이다. 기존 단일 값(`arrivalInterval`, `arrivalIntervalPerDay`, `partySizeWeights`, `orderPatience`, `servePatience`)은 없앤다.
3. 초반(DAY 1~2)은 1~2명 일행만 드문드문 오고 오래 기다려 준다. 후반으로 갈수록 입장 간격과 인내심이 줄고 3~4명 일행이 늘어난다. 값은 docs/GAME_DATA.md 7장에 둔다.

## 검토한 대안

- DAY 1 값과 DAY 15 값만 정하고 사이를 자동 계산: 특정 DAY만 조절하기 어려워 사용자가 DAY별 표를 골랐다.
- 메뉴 해금(초반엔 기본 메뉴만 주문): 이번에는 고르지 않았다. 필요하면 표에 열을 추가한다.

## 결과

- 초반 난이도가 낮아지고, 15일 동안 단계적으로 어려워진다. Inspector 에서 DAY별로 직접 조절할 수 있다.
- 청소 요청 빈도(`cleaningInterval`, 매일 ×0.92)는 그대로라 하루가 짧아진 만큼 하루 청소 요청 수도 줄어든다.
- 이미 만든 `GameBalance.asset` 에는 예전 `secondsPerGameHour` 값(120)이 저장돼 있어서 Inspector 에서 50 으로 바꿔야 한다.
